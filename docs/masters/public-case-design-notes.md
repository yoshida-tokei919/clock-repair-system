# 事例公開 / PublicCase設計メモ

作成日: 2026-06-06

このファイルは、事例公開 / PublicCase設計の正本メモとして扱う。

## 基本方針

事例掲載に合わせて業務アプリ設計を歪めない。
先に業務アプリ側の入力構造・明細構造を整える。
PublicCaseは、その構造化データを公開用にスナップショット化して使う。

## レイヤー分離

部品マスタ:

- 部品交換・購入・在庫・価格・サイズ・写真・仕入先・海外検索などのためのマスタ。

作業マスタ:

- 案件入力・作業内容・処置・技術料・B2B/B2C表示名のためのマスタ。

PublicCase:

- 公開事例用スナップショット。
- 部品マスタや作業マスタを直接表示しない。
- Repair明細 / EstimateItem / RepairLineItem に保存されたスナップショットを元に生成する。

## PublicCaseの役割

PublicCaseは公開事例専用の別スナップショット。

帳票・共有ページの確定明細を代替しない。

PublicCaseに保存するもの:

- 公開用ブランド表示名。
- ブランドカナ。
- 検索テキスト。
- 公開用タイトル。
- 公開用概要。
- 公開用作業表示名。
- 公開用部品表示名。
- B2B/B2C公開状態。
- B2B/B2C価格表示フラグ。
- 除外理由。
- 警告。
- sourceSnapshot。

## Repair明細との関係

通常Repairでは、先にRepair側で構造化入力と明細スナップショットを確定する。

```txt
Repair明細 / EstimateItem / RepairLineItem
↓
PublicCase下書き
↓
公開レビュー
↓
B2B/B2C公開
```

PublicCase表示時に、作業マスタ、部品マスタ、PricingRuleを後読みしない。

作業マスタや部品マスタを後から変更しても、既存PublicCase表示が勝手に変わらないようにする。

## FMP過去案件との関係

FMP過去案件:

```txt
FMP原文
↓
FMP専用クリーニング
↓
作業マスタへの対応付け
↓
PublicCase候補
```

FMP専用処理:

- 読み仮名削除。
- ○○補正。
- 表記ゆれ整理。
- 複合作業分解。
- 未紐づけPartItem救済。
- カテゴリ推定。
- brand-kana-approvedによるブランドカナ付与。
- コピー含有Case除外。

FMP専用クリーニングや推定を、新アプリ通常Repairへ持ち込まない。

## 新アプリ通常Repairとの関係

新アプリ通常Repair:

```txt
内装修理 / 外装修理
↓
カテゴリ
↓
部品名
↓
作業 / 処置
↓
詳細
↓
価格
↓
Repair明細
↓
PublicCase下書き
```

通常Repairは最初から構造化入力する。

PublicCaseはその結果を公開用にスナップショット化する。

## B2B/B2C表示方針

B2C:

- 価格非表示を基本とする。
- 一般ユーザー向けに作業名・部品名を丸める余地を残す。
- 内部管理文言は表示しない。

B2B:

- `showPriceB2b = true` かつ正の価格のみ表示する。
- 0円は表示しない。
- 未紐づけPartItem価格は表示しない。
- 部品代ラベルは使わず、必要なら「交換部品」とする。
- 内部管理文言は表示しない。
- コピー表記は表示しない。

## コピー含有Case除外

コピーを含むCaseはB2C/B2Bとも掲載しない。

FMP由来でも、新アプリ通常Repair由来でも、公開前レビューで除外できるようにする。

## brand-kana-approvedとの関係

FMP過去案件からPublicCase候補を作る場合、`brand-kana-approved` によるブランドカナ付与をFMP専用処理として扱う。

通常Repairでは、ブランドマスタや入力時の構造化データから公開用ブランド表示名を作る。

## 帳票・共有ページとの関係

PublicCaseは帳票・共有ページではない。

帳票・共有ページ:

- Repair明細 / EstimateItem / RepairLineItem の確定データを読む。

PublicCase:

- 公開事例用の別スナップショットを読む。

どちらも、マスタを後読みして過去表示が変わる設計にしない。

## 旧Excel由来候補の扱い

旧Excel由来候補は、PublicCase正本ではない。

理由:

- FMP過去案件の表記ゆれ・救済ルールが混ざっている。
- 事例掲載用の表示名と、業務入力用の作業マスタが混ざっている。
- 部品マスタと作業マスタの役割が混ざりやすい。
- 帳票・共有ページ・PublicCaseとの接続設計を先に決める必要がある。

旧Excel由来候補は参考資料として扱い、公開事例や通常Repairの正式マスタとしてそのまま実装しない。

