# 簡易版 18 — 配達希望回答を確認する

## 操作

1. 単一Repairは作業完了LINEの回答URL、同じ受付の複数Repairは1つの共有ページを案内する。Repairを `作業完了` にしただけではLINEは送られない。
2. 複数Repairで完成品と未完了品が混在する場合は、先に発送するか全件完成まで待つかをお客様に選んでもらう。対象の受付番号を確認する。
3. 今回発送するRepairグループについて、**希望なし / 日付 / 時間帯 / 日付+時間帯** のいずれかを回答してもらう。希望がなくても `希望なし` を確定してもらう。
4. 配達希望の回答が確定すると、対象RepairのDRAFT Shipmentが作成または再利用され、配達希望が反映される。発送予定一覧で個口、対象Repair、宛先、希望内容を確認する。

![Delivery preference](../assets/screenshots/delivery-preference-admin.png)

単一Repairの旧回答はRepair側にも記録される。複数Repairの回答は今回発送するグループを単位に保存され、別受付や次の個口と混ぜない。対象の重複・不一致がある場合は自動作成せず要確認になる。

DRAFT中はお客様が回答を変更でき、管理者もShipment計画を編集できる。管理者の変更後にお客様が再回答するとShipmentの希望内容が再更新される。ゆうプリクラウド発行依頼でREADYになった後は通常の回答変更をロックし、LINEで個別に連絡してもらう。

**現在の限界:** 回答・DRAFT作成だけでは送り状発行や実発送は進まない。Shipmentへの反映と現在のstatusを確認する。
