# 簡易版 16 — ランニングテスト・最終確認を行う

## 目的

修理作業後の時計をランニングテスト用の場所で管理し、発送前の最終確認を行う。

## 1. 現物をランニングテスト場所へ移す

Repairが `作業完了` で中断中ではない通常ケースでは、推奨StorageLocationは `ランニングテスト中` になる。

![Running test location](../assets/screenshots/running-test-location.png)

`blocked=true` の場合は中断理由が優先されるため、画面の推奨zoneを確認する。部品待ちなら `部品待ち`、その他の中断理由なら `要確認` を優先し、無理にランニングテストへ移さない。

## 2. ScanSessionで保管場所を更新

`保管場所移動` を選ぶ。

1. `ランニングテスト中` のLocationタグ / LOCコードを読む。
2. 時計のPhysicalTagを読む。
3. 対象を確認する。
4. `この保管場所へ移動` を押す。

scanしただけでは移動は確定しない。

## 3. ランニングテスト・最終確認

設定された運用日数を目安に、時計の状態を確認する。

異常や再調整が必要なら発送工程へ進めず、Repairを実際の状態へ戻して対応する。

## 4. 問題がなければ発送・引渡し待ちへ

最終確認後、現物を `発送・引渡し待ち` へ移し、StorageLocationも更新する。

## 現在の制限

現行アプリにはランニングテスト専用の `完了` ボタン・完了日時・結果保存がまだない。

そのため、Shipment画面のランニングテスト完了欄は `判定不可` と表示される。これを「完了済み」と読み替えず、作業者が実物を確認してから次へ進む。
