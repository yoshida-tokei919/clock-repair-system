# 簡易版 25 — B2C前受金・返金・請求

1. B2C Repair詳細の「前受金 / 部品代先払い」で、金額と用途を確認して依頼を作成する。支払待ちの依頼がある間は次を作れない。
2. 顧客はRepair共有ページの支払待ち行からカードCheckoutへ進む。戻り画面だけで入金済みと判断せず、Repair詳細の状態を確認する。**`PENDING`は受領済みではなく、`SUCCEEDED`が入金済み。**
3. 支払待ち前受金を取り消す場合は「依頼を取消」を使う。Stripe側で未払いSessionの取消結果まで確認できない場合は確定しない。結果不明のまま別依頼を作らない。
4. B2C請求書を作る際は「請求書と前受金の充当を確認」で、修理総額、利用可能額、提案額、今回請求額を確認する。必要なら提案額を調整し、「この内容で請求書を作成」で確定する。
5. 入金済み前受金のうち、請求書へまだ充当していない利用可能額はRepair詳細から返金できる。Stripe返金が`PENDING`なら新しい返金を重ねず、「Stripe照合」で結果を確認する。
6. 請求書側のStripe入金も返金操作がある。銀行振込の「外部返金の完了を記録」は送金機能ではなく、**実際の返金を外部で完了した後の記録**である。
7. 請求書取消時は残っている前受金充当を解放するが、返金を自動実行しない。未確定の支払・返金や未返金の請求書入金がある場合は取消できない。
8. 保存済みの古い請求書PDFは変更しない。取消済み請求書のPDFは履歴として残り、再生成・LINE再送はしない。

入金・充当・返金・充当解放・請求書取消は別の状態。結果不明の操作を「失敗」と決めて繰り返さない。詳しくは[詳細版第42章](../full/42_repair-prepayment.md)。
