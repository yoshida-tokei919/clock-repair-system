# 簡易版 受付から納品までの全体像

このページでは、1件のB2C修理を受付して返送・納品完了まで進める基本順序を示す。

## 1. LINE問い合わせを確認

管理画面で新しいInquiryを開き、顧客メッセージ・画像・AIの暫定分析を確認する。

`[画面画像予定: inquiry-review.png]`

## 2. 受付レビュー

ブランド、モデル、Ref.、Cal.、故障内容、希望作業等を確認する。AI候補はそのまま正式値にせず、人が確認する。

## 3. 時計を受け取り、Repairへ案件化

現物到着後、Inquiryの時計候補から正式なWatch / Repairを作成する。必要な時計情報を現物と照合する。

## 4. PhysicalTagを発行

修理袋用ラベルを発行し、時計現物とRepairを対応付ける。QR / NFC / shortCodeは現物識別用として使用する。

`[画面画像予定: physical-tag-panel.png]`

## 5. 見積を作る

修理明細を入力し、価格・作業内容・必要部品を確認する。顧客へ提示する前に内容を最終確認する。

## 6. 顧客承認を確認

顧客共有ページ等からの承認結果を確認する。部品発注や作業開始は、案件の承認条件に従う。

## 7. 部品準備・作業待ち

必要部品がある場合は発注し、揃うまでは部品待ちとして管理する。作業可能になった案件をScheduler / 今日の作業で確認する。

## 8. scanして作業開始

PhysicalTagをscanして対象Repairを確認し、必要な作業タイマーを開始する。scanだけで重要状態を自動確定しない。

`[画面画像予定: today-work-and-scan.png]`

## 9. 修理・ランニングテスト

作業を進め、タイマーを停止する。修理後は必要なランニングテスト・最終確認を行う。

## 10. 作業完了をLINE連絡

Repairが作業完了になった後、管理者が送信内容を確認し、「作業完了をLINE連絡」の明示操作を行う。ステータス変更だけでは自動送信しない。

## 11. 配達希望を確認

顧客がLINE内の案内から配達希望回答ページを開き、希望なし / 日付 / 時間帯 / 日付+時間帯を回答する。

`[画面画像予定: delivery-preference.png]`

## 12. Shipmentを準備

発送予定一覧で宛先、配達希望、対象Repair、PhysicalTag、保管場所等を確認する。

## 13. 梱包内容をscan照合

Shipmentに含まれるRepairのPhysicalTagを連続scanし、入れ忘れ・別案件混入・重複を確認する。全件一致後に最終確認する。

## 14. PhysicalTagをrelease

発送前に対象PhysicalTagを確認し、再利用可能な状態へreleaseする。

## 15. ゆうプリRへ出力

ShipmentからゆうプリR標準フォーマットV3 CSVを出力し、ゆうプリRで送り状を作成する。

## 16. 発送・配達完了を確認

日本郵便の引受・追跡・配達完了との自動連携はTask202/204の完成状況に合わせて、この手順を最終確定する。

実際の簡易版では、各工程を原則1ページに分け、画面画像へ番号・矢印・注意枠を入れる。
