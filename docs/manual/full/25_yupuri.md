# 第25章 ゆうプリR CSV出力と発送履歴プレビュー

## 25.1 現在使える範囲

日本郵便向けには、Shipmentから **ゆうプリR標準フォーマットV3の取込CSVを出力するAPI** と、ゆうプリR発送履歴CSVを **読取プレビューするAPI** がある。`/shipments` の共通画面には、現時点でV3出力ボタンがない。送り状の発行・印刷、郵便局への引渡しはゆうプリR側と現物の作業で確認する。

両APIは管理者認証が必要である。API利用環境が整っていない担当者は、管理責任者に運用方法を確認する。画面に存在しないボタンを探して操作したことにしない。

## 25.2 V3 CSV出力

出力先は `GET /api/shipments/[id]/yupuri-v3`。`[id]` は対象Shipment IDに置き換える。出力できるのは **OUTBOUND・`actualShippedAt = null`・statusが `DRAFT / READY / LABEL_ISSUED / AWAITING_ACCEPTANCE` のいずれか** のShipmentだけで、それ以外は拒否される。宛先はShipment作成時のdestination snapshotを使い、顧客マスタの現住所には戻らない。配達希望日・時間帯を出力用コードへ変換できない場合や文字コードで表現できない文字がある場合は、推測せず出力を拒否する。

| CSV仕様 | 現行値 |
| --- | --- |
| 形式 | ゆうプリR 標準フォーマットV3、100列、headerなし |
| 文字コード | CP932 / Shift_JIS、BOMなし |
| 改行 | CRLF |
| お客様側管理番号 | `SHP-{Shipment.id}` |
| 内容品 | 腕時計 |
| 荷物サイズコード | 現時点では `060` 固定 |

実際の荷物が60サイズ以外になる場合、この固定値を流用しない。荷物サイズをShipment側で管理する後続設計が必要である。CSV取得だけではShipment、Repair、追跡番号、status、送り状発行日時は変わらない。

## 25.3 発送履歴CSVの読取プレビュー

`POST /api/shipments/yupuri-history/preview` は、ゆうプリRの発送履歴CSVを読んで照合候補とエラーを返す管理者用API。現行の取込契約はCP932、BOMなし、CRLF、headerあり6列、1ファイル256 KiB・データ500行まで。`SHP-{id}` 形式のお客様側管理番号でShipment候補を探し、お問い合わせ番号、引受関連日、配達完了日、集約・明細status codeを **候補・raw値** として表示する。

確認済みの意味は `10/0A = 引受予定` のみ。これは実際の郵便局引受を証明しない。実引受・配達完了のcode対応と非空日付の書式は、実CSVの証拠を待つTask202Bの範囲である。重複管理番号、照合不能、追跡番号の競合、形式不正はエラー扱いとする。

プレビューは **読取専用**。追跡番号、Shipment / Repair status、実発送日時、配達完了日時を書き戻さない。`importableLater` のような候補表示も書込承認ではない。履歴取込の共通画面はなく、APIで確認しただけでは配送状態は更新されない。

## 25.4 発送後の現在地

配送会社の引受検知、追跡番号保存、LINE発送通知、配達完了に伴うRepair納品完了の自動化は、現行の業務フローとして完成していない。CSVを出した時点や履歴をプレビューした時点で「発送済み」「配達済み」と記録したことにはならない。実物の引渡し・送り状・配送結果は別途確認し、未実装の自動処理を前提に案件を閉じない。
