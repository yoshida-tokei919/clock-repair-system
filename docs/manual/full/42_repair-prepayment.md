# 第42章 B2C前受金・返金・最終請求への充当

## 42.1 前受金依頼を作る

オンライン前受金の**現在の作成フローはB2Cのみ**。管理者は対象Repair詳細の「前受金 / 部品代先払い」を開き、金額と用途を入力して確認後、「前受金依頼を作成」を押す。金額は50～99,999,999円の整数。同じRepairに支払待ちの依頼がある間は別の依頼を作れない。

Repair詳細には用途、金額、状態、作成日、入金日を表示し、「入金済み合計」と「お支払い待ち」を分ける。**`PENDING`は依頼・決済待ちであり、受領済みではない。**

## 42.2 顧客の支払いと入金確認

B2Cの顧客向けRepair共有ページには、支払待ちと入金済みの前受金を表示する。支払待ち行からStripeのカードCheckoutを開始できる。顧客がCheckoutから戻った時の「結果確認中」は確定通知ではない。署名付きWebhookで支払結果が照合され、`SUCCEEDED`になったものだけを入金済みとして扱う。実運用ではRepair詳細の状態を再確認する。

前受金はRepairと顧客に紐付き、用途を保存する。Checkout時に顧客画面から金額を書き換える経路はない。Checkout Session作成や結果保存が不確実な場合は、同じ処理を別キーで作り直さず、保存済みの同一操作を再利用して照合する。

## 42.3 支払待ち前受金を取り消す

`PENDING`の前受金依頼はRepair詳細から「依頼を取消」で取消できる。ただし、単にアプリ上の行を消す処理ではない。既知のStripe Checkout Sessionを確認し、未払いでopenならStripe側でexpireし、その結果を確認できた場合だけ取消を確定する。

支払済み・complete、Checkout Session IDが不明な試行、通信結果が不確実、または処理中にPayment状態が変化した場合は取消を拒否する。結果不明のまま新しい依頼を作らず、Payment / PaymentAttemptとStripe側の状態を確認する。

## 42.4 最終B2C請求へ充当する

修理案件一覧の請求書一括作成で「請求書と前受金の充当を確認」を開く。顧客グループごとに修理総額、受領済み前受金、利用可能な前受金、今回充当額、今回請求額を確認する。候補は**選択した請求対象Repairに属する`SUCCEEDED`前受金**に限られる。管理者は提案された充当額を確認し、必要なら各額を調整してから「この内容で請求書を作成」で明示確定する。

新しく発行するB2C請求書は、修理総額から有効な前受金充当額を引いた今回請求額を示す。管理者・顧客の支払表示では「今回請求額」と、その後の入金を反映した「未入金残高」を区別する。新規生成PDFも修理総額・前受金充当・今回請求額を表示する。**保存済みの古い請求書PDFは変更されない。**

## 42.5 前受金と請求書支払いを返金する

`SUCCEEDED`のPaymentは返金してもPayment本体を`FAILED`や`CANCELED`へ書き換えない。返金は別の`PaymentRefund`記録として残し、成功した返金額を差し引いて実質の受領額を計算する。

Repair詳細の前受金では、既に請求書へ充当している額を除いた**未充当の利用可能額**を返金対象にする。Stripe前受金で利用可能額があり、返金処理中の記録がない場合は「未充当額を返金」から返金できる。請求書側ではStripe入金を指定額で返金できる。

銀行振込など`MANUAL` Paymentの「外部返金の完了を記録」は、**銀行へ送金する機能ではない**。実際の返金をアプリ外で完了したことを管理者が確認した後、その事実を記録する操作である。

返金が`PENDING`の場合は同じPaymentから別の返金を開始しない。Stripeの外部結果が確定していないときは「Stripe照合」で保存済みの返金記録とprovider結果を照合する。通信エラーを「返金失敗」と決めつけて返金可能額を戻さない。

## 42.6 充当解放と請求書取消

前受金の充当は`PaymentAllocation`、後から解放した額は`PaymentAllocationRelease`として別々に履歴を残す。有効な充当額は、元の充当額から成功した解放額を引いて計算する。過去のAllocation行そのものを削除・上書きして履歴を消さない。

請求書を取り消す場合、残っている有効な前受金充当は同じ処理内で解放され、対象Repairは再び未請求側へ戻る。ただし、未確定のPayment・返金がある場合や、返金されていない請求書入金が残る場合は取消を拒否する。**請求書取消は返金を自動実行しない。** 必要な返金を別に完了・確認してから取消可否を判断する。

取消済み・キャンセル済み請求書の保存済みPDFは履歴として保持し、再生成・LINE再送は行わない。

## 42.7 状態の読み分け

- `Payment.status = SUCCEEDED` — 元の入金が確定した事実。返金後もこの履歴は保持する。
- `PaymentRefund.status = PENDING` — 外部返金結果が未確定。返金済みとは扱わない。
- `PaymentRefund.status = SUCCEEDED` — 返金確定額として残高計算へ反映する。
- `PaymentAllocation` — 前受金を請求書へ充当した履歴。
- `PaymentAllocationRelease` — 充当額を後から解放した履歴。

入金、充当、返金、充当解放、請求書取消は別の事実である。画面上の残高だけで過去履歴を推測せず、必要に応じて各記録を確認する。二重処理防止は[第36章](36_duplicate-safety.md)、Stripeとの接続境界は[第34章](34_external-integrations.md)を参照する。
