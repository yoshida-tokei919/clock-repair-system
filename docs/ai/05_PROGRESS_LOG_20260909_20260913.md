## Task166: 部品発注完了後の案件status逆戻り修正

### 発見した症状

部品注文あり案件:

```text
部品待ち(未注文)
→ 部品待ち(注文済み)
→ 部品入荷済み
→ 発注管理で「案件へ割当」
```

server/一覧は `作業待ち` になるが、案件画面が古い `部品入荷済み` をcurrent表示する。
さらに過去received情報により `作業待ち / 作業中 → 部品入荷済み` へ逆戻りし得た。

### 根本原因

1. `RepairEntryForm` がactiveな `OrderRequest` ではなく、部品明細の表示label / 過去received情報から案件statusを再計算していた。
2. `作業待ち / 作業中` もparts status自動反映対象だったため、過去receivedで上書きされ得た。
3. 発注管理からブラウザ履歴で案件画面へ戻る経路が `popstate` だが、`useAutoRefreshOnReturn` が監視していなかった。
4. `router.refresh()` 後も `RepairEntryForm` の `status / persistedStatus / statusLog / orderList` が最新 `initialData` と同期されていなかった。

### 確定仕様

active OrderRequest:

- `pending`
- `ordered`
- `received`

inactive/completed:

- `assigned`

status連携:

- pendingあり → `部品待ち(未注文)`
- pendingなし + orderedあり → `部品待ち(注文済み)`
- activeがすべてreceived → `部品入荷済み`
- 最後のreceivedをassigned → `作業待ち`
- assigned済み部品や過去receivedだけで `部品入荷済み` に戻さない
- `作業待ち / 作業中` で新規pendingができた場合は `部品待ち(未注文)` へ戻せる

### local修正内容

対象:

- `src/lib/repair-parts-status.ts`
- `src/components/repairs/RepairEntryForm.tsx`
- `src/app/api/orders/[id]/route.ts`
- `src/lib/repair-parts-status.test.ts`
- `src/hooks/use-auto-refresh-on-return.ts`

追加対応:

- active OrderRequestをsource of truthに変更
- assignedをactive集計から除外
- refresh後に `status / persistedStatus / statusLog / orderList` を最新initialDataへ同期
- `popstate → router.refresh()` を追加

local verification:

- `pending → ordered → received` 正常
- `received → assigned` で一覧・案件画面とも `作業待ち`
- browser backでもCtrl+R不要で `作業待ち` が青表示
- `作業待ち → 作業中` 正常
- `部品入荷済み` へ逆戻りしない
- 新規テスト案件で不要な `作業中` 日付なし
- `npx tsc --noEmit --incremental false` 成功
- related Node tests 14件成功（Case A〜E）
