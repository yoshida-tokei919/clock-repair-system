# AI Task 058: 内装修理の掲載99件ルールをFMP過去データ変換ルールへ反映する

## 目的

FMP由来の内装修理作業名ユニーク320件について、公開事例掲載に使う変換ルールを安全に実装・整理する。

今回の最重要方針は以下。

- 全320件のうち、ユーザーが確認・修正した99件だけを掲載候補として扱う
- 残り221件は、内容がそれらしくても **未レビューのため掲載しない**
- 原文が `交換` の98件は、作業名としては一律 `交換技術料` でよい
- `交換` 98件について、交換対象部品はFMPの `内装部品1〜3` / `内装部品価格1〜3` 側で判断する
- したがって `交換` を無理に `ゼンマイ交換技術料` などへ分解しない

## 基本ルール

- 既存コードを壊さない
- 不要なリファクタリング禁止
- 指示範囲外の変更禁止
- 最小差分で進める
- `git add .` 禁止
- commit / push 禁止
- `.next-dev.err.log` は触らない
- `tsconfig.tsbuildinfo` が更新されたら戻す
- 作業開始時と完了時に `git status --short` を確認する
- 必要に応じて `npx tsc --noEmit` を実行する
- `npm run lint` は現状 Next.js ESLint 初期設定プロンプトで止まるため、無理に実行しなくてよい

## 実装・整理要件

### 1. 現状調査

まず以下を確認する。

```powershell
git status --short
```

次に、FMP過去データ変換・公開事例生成・作業マスタ・内装修理マスタに関係する既存ファイルを調査する。

検索例:

```powershell
rg "FMP|FileMaker|公開事例|case|repair case|内装修理|外装修理|掲載|B2B|B2C" docs src prisma scripts
```

既存の変換ルール・スクリプト・データ置き場がある場合は、それに合わせる。
無い場合は、まずドキュメントと変換マスタデータだけを作る。

### 2. ルールを明文化する

以下の方針を、ドキュメントまたは変換マスタ内に明確に残す。

```txt
内装修理の公開事例掲載対象は、FMP由来の内装修理作業名ユニーク320件のうち、ユーザー確認済み99件のみ。
未レビューの221件は掲載しない。

原文「交換」98件は、作業名としては一律「交換技術料」とする。
交換対象部品は、別途FMPの内装部品欄に記録されるため、作業名側では部品名に分解しない。
```

### 3. 変換マスタの形にする

既存実装がなければ、まずJSONまたはTS定数で変換マスタを作る。
形式は既存プロジェクト方針に合わせる。
迷う場合は、次のようなTS定数を候補にする。

```ts
export type InternalRepairPublicCaseRule = {
  sourceWorkName: string;
  normalizedWorkName: string;
  publishStatus: 'publish' | 'exclude_unreviewed' | 'exclude_not_public' | 'needs_final_review';
  category?: string;
  partName?: string;
  action?: string;
  note?: string;
};
```

必須要件:

- 99件は `publish` または必要なら `needs_final_review`
- 221件は `exclude_unreviewed`
- 掲載対象外と判断済みのものは `exclude_not_public`
- `交換` は `normalizedWorkName: '交換技術料'`
- `交換` のnoteに「交換部品欄参照」と分かる情報を残す

### 4. B2B/B2C表示ルール

既存の公開事例表示ロジックがある場合、以下の方針に矛盾しないようにする。

#### B2B

- 技術料と部品代を分けて表示する
- 例:

```txt
交換技術料 3,000円
ゼンマイ 2,000円
```

#### B2C

- 価格は表示しない
- 表示は短い作業名でよい
- 例:

```txt
交換技術料
```

ただし、B2C表示で `技術料` を出すかどうかは既存の公開事例表示方針に合わせる。
今回のタスクでは、無理にUI文言を変更しない。

### 5. Excelからの反映

`内装修理_部品名ドリルダウンレビュー用_掲載99件反映版.xlsx` の以下のようなシートを確認する。

- `掲載判定_全件`
- `掲載対象_確認済99内`
- `掲載しない_未レビュー等`
- `マスタ追加_ユーザー修正反映`

このExcelの内容を正とする。

重要:

- Excel上でユーザーが修正した正規作業名を優先する
- 自動判定だけで未レビュー221件を掲載候補へ戻さない
- `交換` 98件は `交換技術料` で固定する

### 6. できればテストまたは検証スクリプトを追加

既存テスト構成が軽ければ、最低限以下を検証する。

- 全320件中、掲載候補が99件由来であること
- 未レビュー221件が掲載されないこと
- 原文 `交換` が `交換技術料` へ変換されること
- 原文 `交換` が部品名付き作業名へ勝手に分解されないこと

テスト追加が重い場合は、検証用スクリプトまたはドキュメント内のチェックリストでもよい。
