# 057: B2B / B2C 修理事例掲載設計 決定事項

## 目的

FMP過去修理データと今後の修理案件データを、B2B / B2C の修理事例として活用する。

ただし、公開事例・SNS投稿機能へ進む前に、業務アプリ側の作業カテゴリ・作業名・外装修理マスタを整える。

---

## 基本方針

B2B事例とB2C事例は別に作る。

現時点で決まっている最大の違いは、価格表示の有無。

```txt
B2C事例 = 価格非表示
B2B事例 = 価格表示
```

B2Bでは、価格を公開して業務利用に役立ててもらう。

B2Cでは、価格は公開しない。

---

## B2C公開事例

### 想定読者

一般のお客様。

### 目的

- 集客
- 修理対応範囲の訴求
- 難しい修理・珍しい修理の実績紹介
- サイト訪問者が似た事例を見つけやすくする

### 表示候補

```txt
ブランド
モデル名
REF
Cal
修理内容
交換部品名
写真
補足コメント
```

### 非表示

```txt
価格
内装修理技術料
外装修理技術料
外注料金
部品価格
合計金額
顧客情報
取引先情報
内部メモ
原価
利益
```

### 作業名表示

B2Cでは、短くわかりやすい作業名にする。

例：

```txt
ガラス交換
リューズ交換
ケース仕上げ
オーバーホール
```

`ガラス交換を行いました` ではなく、事例タグ・作業名として `ガラス交換` のように表示する。

### 価格

B2C事例では価格を表示しない。

将来的に価格表示を検討する場合でも、B2Cでは一般向けの合算表記が自然。

例：

```txt
ガラス交換 5,000円
```

ただし現時点では価格非表示で固定。

## B2B公開事例

### 想定読者

業者・取引先。

### 目的

- 業務上の参考価格提示
- 修理可否判断の補助
- 似た時計・似た修理の参考事例検索
- B2B向けの価格感共有

### 表示候補

```txt
ブランド
モデル名
REF
Cal
修理内容
交換部品名
内装修理技術料
外装修理技術料
外注料金
部品価格
合計金額
写真
B2B向け補足コメント
```

### 価格表示

B2Bでは価格を表示する。

技術料と部品代は分けて表示する。

例：

```txt
ガラス交換技術料 3,000円
ミネラルクリスタル 2,000円
合計 5,000円
```

これはB2B見積書・納品書・B2B事例紹介で共通する方向。

---

## B2C見積書・納品書との関係

B2Cの見積書・納品書で、技術料と部品代を分けるか、合算表示にするかは未決定。

候補：

```txt
案A: ガラス交換技術料 3,000円 / ミネラルクリスタル 2,000円
案B: ガラス交換 一式 5,000円
```

B2C書類表示は別途検討する。

## 写真の扱い

写真は必須ではない。

過去データでは写真がある案件は一部のみと思われる。

初期方針：

```txt
まずCSVテキストデータだけで事例候補を整理
↓
公開候補を選定
↓
必要な案件だけ写真を後から紐づけ
```

写真をCSV / Excelに直接埋め込まない。

写真は別フォルダ・別ストレージで管理し、事例データ側にはファイル名またはURLを持たせる。

## 公開対象外データ

以下は公開事例候補に出さない。

```txt
顧客名
顧客電話番号
顧客住所
顧客メールアドレス
顧客管理番号
内部メモ
備考
連絡事項
取引先情報
仕入価格
原価
利益
その他個人情報や内部情報を含む可能性があるもの
```

投稿用・公開用コメントは、既存の備考や連絡事項を流用しない。

専用フィールドを用意する。

例：

```txt
B2C公開コメント
B2B向け補足
Instagram用コメント
ハッシュタグ
```

## B2B / B2C 表示変換

同じ内部データから、表示先ごとに見せ方を変える。

### 内部データ

```txt
対象部品: ミネラルクリスタル
処置: 交換
技術料: 3,000円
交換部品: ミネラルクリスタル
部品価格: 2,000円
```

### B2B表示

```txt
ガラス交換技術料 3,000円
ミネラルクリスタル 2,000円
```

### B2C事例表示

```txt
ガラス交換
```

## 公開事例検索方針

B2C公開事例検索は、フリーワード検索ではなく候補選択式を基本とする。

```txt
ブランド選択
↓
モデル候補が絞り込まれる
↓
REF候補が絞り込まれる
↓
候補の事例一覧
```

理由：

- 表記ゆれが減る
- brandId / modelId / ref で安定検索できる
- 知識の少ないお客様も候補を見ながら探せる
- マニアックなお客様も素早く絞り込める

フリーワード検索は初期実装では不要。

## 公開タグ方針

業務アプリ側の詳細カテゴリを、そのままB2Cに出すと細かすぎる。

B2C向けには公開タグへ変換する。

候補：

```txt
オーバーホール
止まり・精度不良
ガラスまわり
リューズ・巻芯まわり
防水・水入り
外装まわり
ブレス・ベルトまわり
針・文字盤まわり
部品製作・加工
クォーツ修理
クロノグラフ修理
```

ただし、公開タグは業務カテゴリ定義後に最終決定する。

---

## 外装修理マスタとの関係

外装修理マスタでは、以下のように構造化する。

```txt
外装部品カテゴリ
外装部品名
部品属性
処置
処置詳細
```

B2C / B2B事例では、この構造化データから表示名を生成する。

例：

```txt
外装部品名: ガラス
処置: 交換
B2B表示: ガラス交換技術料
B2C表示: ガラス交換
```

---

## 価格の扱い

### B2C

価格非表示。

### B2B

価格表示。

技術料と部品代を分けて表示。

### 外装修理価格入力

外装修理は価格がまちまちになりやすいため、初期実装では価格自動入力を主軸にしない。

```txt
外装修理の技術料 = 都度手入力
```

将来的には過去価格を参考候補として表示する余地は残す。

---

## 投稿機能との関係

将来的には、各案件詳細ページから投稿・公開候補を作りたい。

対象：

```txt
Instagram
HP事例 B2C
HP事例 B2B
将来的にX / Googleビジネスプロフィール等
```

ただし、これは記事をゼロから書く機能ではない。

Repair案件1件を素材にして、定型フィールドから自動生成する機能とする。

公開事例・SNS投稿機能へ進む前に、業務アプリ側の作業カテゴリ・作業名・外装修理マスタを定義する。

---

## 投稿設定

投稿設定は案件詳細で毎回チェックさせるのではなく、別の投稿設定ページで一括設定する方針。

設定を後から変えても、過去投稿は投稿時のスナップショットのままとする。
