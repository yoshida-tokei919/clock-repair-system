# Task 113: Fix unsafe PartsMaster partRef normalization

## 問題

`PartsMaster.partRefs`の重複比較で、部品番号内の記号を根拠なく削除していた。

影響例:

- `24-603`
- `24603`
- `24.603`
- `24/603`

これらは同一部品番号とみなしてよいドメインルールがないため、同一扱いしない。

## 原因

以下の比較helperが、比較時に空白、ハイフン、ドット、スラッシュを削除していた。

- `src/lib/parts-master.ts`
  - `normalizeRefToken`
- `src/lib/parts-master-search-info.ts`
  - `normalizePartRefForCompare`

また、`parts-master-search-info.ts`の`splitPartRefs`は内部空白も単一空白へ丸めていた。

## 修正箇所

- `src/lib/parts-master.ts`
- `src/lib/parts-master-search-info.ts`

## 修正後の比較ルール

- 前後空白は`trim()`で除去する
- ハイフン`-`は削除しない
- ドット`.`は削除しない
- スラッシュ`/`は削除しない
- その他partRef内部の記号も削除しない
- 大文字小文字の変換も行わない
- 数字だけへの変換、曖昧一致、メーカー別変換ルールは追加しない

## 確認内容

ロジック確認:

- `"24-603"` と `"24-603"` は同一
- `" 24-603 "` と `"24-603"` は同一
- `"24-603"` と `"24603"` は別
- `"24-603"` と `"24.603"` は別
- `"24-603"` と `"24/603"` は別

`mergePartRefs`確認:

- 既存`24-603`へ`24603`を追加すると、`24-603, 24603`になる
- 既存`24-603`へ`24.603`を追加すると、`24-603, 24.603`になる
- 既存`24-603`へ`24/603`を追加すると、`24-603, 24/603`になる
- 既存`24-603`へ` 24-603 `を追加すると、重複としてskipされる

## 次工程への注意

- `part-search.ts`の`expandPartRefVariants`はWeb検索query生成用であり、今回の重複比較とは別用途。Task 113では触らない。
- PartsMaster成長フローの重複確認では、この保守的なpartRef比較を土台にする。
- ハイフン違い、ドット違い、スラッシュ違いを参考候補として出す場合でも、重複確定には使わない。
- メーカー別の明確な部品番号体系ルールが確認できた場合のみ、別Taskで個別正規化を設計する。
