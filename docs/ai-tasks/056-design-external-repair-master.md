# 056: 外装修理マスタ設計 決定事項

## 目的

FMP過去データの外装修理内容・外装部品情報を、今後の時計修理業務アプリで再利用できる形に整理する。

目的は以下。

- 外装修理の入力名を統一する
- 表記ゆれを減らす
- 過去データを今後のマスタ構造に合わせて変換する
- 新規案件入力時も同じ定義を使えるようにする
- B2B / B2C の過去修理事例掲載へ転用できる構造にする

---

## 基本方針

外装修理は、単純な自由入力の作業名ではなく、以下の構造で入力する。

```txt
外装修理
↓
外装部品カテゴリ
↓
外装部品名
↓
必要に応じて部品属性
  - 位置
  - 素材
  - サイズ
  - バリエーション
↓
処置
↓
処置詳細
↓
技術料
```

外装部品カテゴリ・外装部品名は、既存の外装部品マスタを正とする。

## 外装部品マスタ更新方針

既存マスタは固定ではなく、FMP過去データの確認結果を反映して更新していく。

```txt
既存外装部品マスタ
↓
FMP過去データで不足・表記ゆれを発見
↓
ユーザー確認
↓
既存マスタへ追加・修正
↓
次回レビューでは更新後マスタを正として判定
```

### 表記ゆれ・別名

- `中留` は `クラスプ` に正規化する。
- `中留` は `クラスプ` の別名候補として扱う。
- `尾錠` は `バックル` に寄せず、外装部品マスタに新規追加する。
- `尾錠` の追加先カテゴリは `bracelet_band / ブレス・バンド`。

### Excel上の「新規」の意味

レビューExcel内でユーザーが `新規` / `（新規）` と記載したものは、マスタへ追加してほしいという意味で扱う。

## 位置情報の扱い

`位置` は処置ではなく、部品特定のための属性。

特にクロノグラフでは、同じような見た目の針が `12H / 3H / 6H / 9H` に存在するため、部品検索・部品特定に位置情報が必要になる。

例：

```txt
分積算針・位置 3H
時積算針・位置 6H
クロノ秒針・位置 センター
```

過去データに `3H / 6H / 9H / 12H / センター` が出てきた場合、原則として針・インデックス・プッシャー等の位置属性として扱い、処置とは見なさない。

## 処置マスタ

処置はマスタ化する。

理由：

- 表記ゆれ防止
- 入力候補化
- B2B / B2C 表示変換
- 過去データ整理
- 将来的な集計

## 処置詳細マスタ

処置詳細もマスタ化する。

ただし、処置詳細は全体一覧で表示せず、以下のドリルダウン条件に紐づける。

```txt
外装部品名
+
処置
+
処置詳細
```

これにより候補が増えすぎる問題を防ぐ。

### 処置詳細の例

```txt
針 × 修正 × ハカマ
針 × 修正 × 曲がり
針 × 修正 × 擦れ
針 × 塗装 × 蓄光
リューズ × 除去 × 折れ込み巻芯
```

### 入力方針

- 処置詳細は候補選択式。
- 候補がない場合は新規入力できる。
- 新規入力値は次回候補化する。
- 処置詳細は、外装部品マスタには反映しない。

---

## 仕上げ系の例外扱い

仕上げ系は通常の `外装部品名 × 処置` に無理に入れず、例外作業名マスタとして扱う。

理由：

- 対象部品がケース・ブレスレットなど複数になる
- 金額で内容が変わる
- オーバーホールとのセット割引がある
- 過去データ上の `仕上げ` / `簡易仕上げ` が曖昧

### 例外作業名候補

```txt
ケース・ブレスレット仕上げ
ケース仕上げ
ブレスレット仕上げ
ケース・ブレスレット簡易仕上げ
ケース簡易仕上げ
ブレスレット簡易仕上げ
```

### FMP過去データの仕上げ判定ルール

```txt
仕上げ × 10,000円 = ケース・ブレスレット仕上げ
仕上げ × 8,000円 = ケース・ブレスレット仕上げ（OHセット割引）
仕上げ × 5,000円 = ケースのみ、またはブレスレットのみ。原則確認対象
簡易仕上げ × 5,000円 = ケース・ブレスレット簡易仕上げ、または片方のみ簡易仕上げ。原則確認対象
```

上記以外の金額・組み合わせはユーザー確認対象。

## 部品代と技術料の分離ルール

FMP過去データでは、作業欄と部品欄の使われ方が混在している。

### パターンA: 技術料と部品代が分かれている

例：

```txt
外装修理内容: 交換
外装修理技術料: 2,000
外装部品: ガラス
外装部品価格: 2,000
```

この場合：

```txt
対象部品: ガラス
処置: 交換
技術料: 2,000
部品代: 2,000
B2B表示: ガラス交換技術料 2,000円 / ガラス 2,000円
B2C表示: ガラス交換
```

### パターンB: 作業欄に部品名込みの作業名があるが、部品欄にも部品がある

例：

```txt
外装修理内容: ガラス交換
外装修理技術料: 3,000
外装部品: ガラス
外装部品価格: 2,000
```

この場合、作業欄の `ガラス交換` は技術料名と判断しやすい。

```txt
ガラス交換技術料 3,000円
ガラス 2,000円
```

### パターンC: 作業欄に部品名込みの作業名があり、部品欄が空

例：

```txt
外装修理内容: ガラス交換
外装修理技術料: 5,000
外装部品: 空欄
```

この場合、部品代込みの可能性が高い。勝手に分解せず確認対象にする。

---

## 交換部品複数に対して技術料が1つの場合

交換部品が複数あり、技術料が1つの場合は、自動配分しない。

例：

```txt
交換技術料 3,000円
外装部品1: リューズ
外装部品2: チューブ
```

この場合はユーザー確認対象とし、都度配分またはまとめ方を決める。

---

## オーバーホールと部品交換の関係

オーバーホール作業が含まれている場合、部品交換技術料は無料にしていることが多い。

```txt
OHあり + 部品交換あり
```

の場合、部品交換技術料が別途有料かどうか怪しいものは確認対象にする。

---

## 巻芯・折れ込み巻芯の扱い

`巻芯交換` と `折れ込み巻芯除去` は同じ扱いにしない。

### 巻芯交換系

```txt
巻芯交換
巻芯延長
巻芯別作
```

これらは内装寄り、または確認対象。

### 折れ込み巻芯除去系

```txt
折れ込み巻芯除去
折込巻芯除去
折込み巻芯除去
リューズ折込巻芯抜き
```

これは外装のリューズまわり作業として扱う。

```txt
対象部品: リューズ
処置: 除去
処置詳細: 折れ込み巻芯
表示名: リューズ折れ込み巻芯除去
```

## 価格入力方針

外装修理は価格がまちまちになりやすいため、初期実装では価格自動入力を主軸にしない。

理由：

- ブランド
- モデル
- REF
- 部品状態
- 部品入手性
- 純正 / FIT / 加工
- 作業難度
- 取引先
- オーバーホールとセットかどうか

などで価格が変動しやすい。

### 確定方針

```txt
外装修理の技術料 = 都度手入力
```

ただし、将来的に過去価格を参考候補として表示する余地は残す。

```txt
参考候補:
ROLEX × ガラス × 交換: 3,000円 / 5,000円
ガラス × 交換: 2,000円 / 3,000円 / 5,000円
```

これは自動入力ではなく、参考表示とする。

---

## 表示名ルール

### アプリ内部 / B2B

技術料と部品代を分けて表示する。

例：

```txt
ガラス交換技術料 3,000円
ミネラルクリスタル 2,000円
```

### B2C事例

短い作業名で表示する。

例：

```txt
ガラス交換
```

B2C事例では価格を表示しない。

---

## 今後のレビュー方針

過去FMPデータは、以下に分類してレビューする。

```txt
1. 自動変換できる候補
2. カタリが高確度で提案できる候補
3. 高額修理候補
4. ユーザー確認が必要な候補
5. 掲載対象外
6. 内装修理へ移動
```

高額修理は、外装修理技術料10,000円以上を優先確認対象とする。

---

## 更新履歴メモ

- 外装部品名は既存外装部品マスタを正とする。
- `Mineral = ミネラルクリスタル` とする。
- `ガラス / 風防 / ミネラルクリスタル / サファイアガラス` は自動同一視しない。
- `中留` は `クラスプ` へ正規化。
- `尾錠` は `ブレス・バンド` へ新規追加。
- Excel内の `新規` / `（新規）` は追加希望として扱う。
- 処置はマスタ化する。
- 処置詳細も、外装部品名 × 処置 に紐づくマスタとして扱う。
- 外装修理の価格は都度手入力を基本とする。
