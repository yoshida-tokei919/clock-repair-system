# LINE sender watchdog and auth revalidation — 2026-10-24

Production: pending. No Scheduled Task was registered or changed, and no live LINE or auth operation was run for this Task.

- The opt-in `install-line-manager-sender-watchdog-task.ps1 -Enable` registers a separate five-minute Windows task. Preview mode is the default. Registration and activation require a later operator decision.
- The watchdog only inspects the existing `ClockRepair-LineManagerSender` task. If it is `Running`, it reports `status=running`. If it is enabled and `Ready`, it requests one start after a persisted 15-minute cooldown. It never invokes the worker or auth bootstrap itself. Missing, disabled, unexpected, or invalid state fails closed. A named mutex serializes watchdog runs.
- Every watchdog result is one sanitized `status=...;alertDue=true|false` line. `alertDue` is recorded before emission and suppressed for six hours, then reset when the sender is running. The state under `%LOCALAPPDATA%\clock-repair-system\line-manager-sender` contains only timestamps. n8n parsing and Slack posting are **pending**; no endpoint or workflow is introduced here.
- The sender exits successfully only after a completed cycle when its monotonic runtime reaches 60 minutes. Its existing launcher then runs `line_manager_auth_storage.py --ensure-valid` on the next task start, before the worker can send. The launcher, singleton and operation locks, outbox claim/fence, idempotency, and reconciliation are unchanged.
- Immediately before evidence persistence and fence, the sender's existing live Manager history read checks access. Only lineoa's typed `InteractiveLoginRequired` from that read marks auth expired. Pre-send failure still acknowledges `PRE_SEND_FAILED`; reconciliation history failure remains pending. The worker releases the cycle's operation lock, then holds the same shared lock for one dedicated-profile `bootstrap()` attempt per run. It drops the stale adapter and recreates it on the next cycle. Challenge or bootstrap failure stops the worker with a sanitized failure. Generic network/read failures and unknown POST outcomes never trigger auth recovery or blind resend.

Before any production activation, independently review the final diff and task action, then explicitly approve the watchdog registration. The watchdog can restart the already authorized `-AllowSend` sender task, so a start may process an eligible approved outbox after the launcher's auth gate succeeds.
