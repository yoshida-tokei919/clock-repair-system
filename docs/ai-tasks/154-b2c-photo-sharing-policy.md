# B2C共有ページ・案件写真分類・公開制御方針

更新日: 2026-09-08

## 目的

B2C共有ページを、LINEでの相談と競合しない「進捗・写真・確定見積・承認」のポータルとして整理する。

同時に `RepairPhoto（案件写真）` を、共有ページ・PublicCase（事例公開）・SNS投稿候補へ安全に再利用できる写真基盤へ整理する。

基本方針:

```txt
LINE = 相談・修正・会話
共有ページ = 進捗・写真・確定見積・承認・帳票
修理アプリ = 写真分類・公開可否・案件記録の正本
```

## 2. B2C共有ページ 最終UI方針

### 会話導線

共有ページ内のコメント欄は使用しない。

顧客の次の行動は原則2択にする。

```txt
この内容で進める
LINEで相談する
```

相談・修正内容の本文はLINEトークで扱う。

### 見た目

- 広告的なキャッチコピーは置かない。
- 情緒と視覚的メリハリは時計写真、ステータス、金額、card構成で出す。
- 高級時計ブランドLPではなく、信頼できる修理ポータルを目指す。
- `主な修理内容` は `見積内容` と重複するため廃止する。

### ご案内

共有ページの `ご案内` は `Repair.customerNote（お客様連絡欄）` をそのまま表示する。

```txt
customerNoteあり -> ご案内に表示
customerNote空欄 -> ご案内も空欄（デフォルト文章を出さない）
```

## 3. ステータス別の写真・見積表示

### 受付〜承認待ち

表示:

- ステータス
- ブランド / モデル / Ref等
- 税込金額
- 受付時の時計正面写真
- 受付時の時計裏面写真
- 見積内容
- ご案内
- `この内容で進める`
- `LINEで相談する`

写真はスマホで収まりの良い配置を優先する。正面・裏面を無理に小さく横並びにせず、実画面で読みやすい構成を選ぶ。

### 作業中

上部では受付〜承認時と同様に以下を維持する。

- ステータス
- ブランド / モデル
- 税込金額

作業中写真:

- オーバーホール時: ムーブメント / 裏蓋開放・分解状態写真
- その他修理: 修理箇所写真

見積内容:

- 折りたたみ可能
- 初期状態は閉じる

相談導線はLINEへ寄せる。

### 作業完了

完了時の既存表示方針は大きく変更しない。

完成写真を表示する。

## 4. 現在のRepairPhoto構造

現行schemaには既に以下がある。

```txt
RepairPhoto
- id
- repairId
- category
- storageKey
- fileName
- mimeType
- createdAt
```

既存 `category（カテゴリ）` を正式に **撮影箇所** として利用する。

新しく撮影箇所用の重複カラムを追加しない。

---

## 5. 撮影箇所 category

標準値:

```txt
front         = 時計正面
crown_side    = 側面（リューズ側）
back          = 時計裏面
bracelet      = バンド / ブレス
movement_open = 裏蓋開放・ムーブメント
repair_detail = 修理箇所
other         = その他
```

既存 `general` は旧データ互換として残し、原則 `other` 相当として扱う。

---

## 6. 撮影工程 captureStage

同じ `front（正面）` でも受付時と完成時を区別する必要があるため、撮影工程を別軸で持たせる。

候補:

```txt
reception  = 受付時
work       = 作業中
completion = 作業完了
```

例:

```txt
reception + front  = 受付時の正面写真
completion + front = 完成時の正面写真
```

`captureStage` の具体的なschema追加方法は現行ローカルschema/APIを調査してから決める。schemaを推測して実装しない。

---

## 7. 写真ごとの利用可否

写真1枚ごとに以下を独立して持たせる方向。

```txt
customerVisible   = 共有ページOK
publicCaseVisible = 事例OK
snsVisible        = SNS OK
```

重要:

- `publicCaseVisible = true` は自動公開を意味しない。
- `snsVisible = true` も自動投稿を意味しない。
- どちらも「公開候補として使用してよい」という意味。
- 実際のPublicCase公開 / SNS投稿は最終確認を残す。

---

## 8. アプリ全体の写真公開デフォルト

管理画面等に `写真公開デフォルト設定` を用意する方向。

初期候補:

| 撮影箇所 | 共有ページ | 事例 | SNS |
| --- | --- | --- | --- |
| 時計正面 | ON | ON | ON |
| 時計裏面 | ON | ON | OFF |
| リューズ側 | OFF | OFF | OFF |
| バンド | OFF | OFF | OFF |
| ムーブメント | ON | ON | ON |
| 修理箇所 | ON | ON | ON |
| その他 | OFF | OFF | OFF |

全体デフォルトは **新規写真作成時の初期値のみ** とする。

後からデフォルトを変更しても、既存写真の設定を自動変更しない。

## 9. 案件写真タブのUI

案件の `写真` タブで写真カードごとに以下を確認・変更できるようにする。

```txt
撮影工程
撮影箇所
[ ] 共有ページOK
[ ] 事例OK
[ ] SNS OK
```

通常は撮影箇所に応じたデフォルト値を自動入力し、毎回手作業で設定しなくてよいようにする。

### 写真共有設定

写真タブ上部に `写真共有設定` ボタンを置く方向。

押すと案件内写真を一覧で確認・一括変更できる。

例:

| 写真 | 撮影工程 | 撮影箇所 | 共有 | 事例 | SNS |
| --- | --- | --- | --- | --- | --- |
| 正面 | 受付時 | 時計正面 | ON | ON | ON |
| 裏面 | 受付時 | 時計裏面 | ON | ON | OFF |
| ムーブ | 作業中 | ムーブメント | ON | ON | ON |

写真カード上の個別設定と、一括設定画面の両方を用意する方向。

## 10. お客様による投稿拒否

B2C共有ページの見積確認時に、顧客が選択できる投稿拒否チェックを追加する方向。

文言例:

```txt
[ ] 修理写真の事例・SNSへの掲載を希望しない
```

この値は **案件単位の最上位ルール** とする。

### 投稿拒否ON

アプリ側では:

```txt
共有ページOK -> 通常どおり選択可能
事例OK       -> OFF固定 / disabled
SNS OK        -> OFF固定 / disabled
```

すでに写真の `事例OK / SNS OK` がONでも、安全側でOFFへ落とす。

アプリ写真タブ等には、拒否理由が分かる表示を出す。

例:

```txt
お客様が事例・SNSへの写真掲載を希望されていません
```

### 投稿拒否解除

- `事例OK / SNS OK` を再び操作可能にする。
- 過去のON状態は自動復元しない。
- 必要な写真だけヨシダ側で明示的に再選択する。

### 共有ページ

共有ページは顧客本人向けの非公開ページなので、投稿拒否とは別扱い。

投稿拒否ONでも `共有ページOK` は利用できる。

---

## 11. 設定優先順位

写真公開の優先順位は次のとおり。

```txt
お客様の投稿拒否
    ↓
案件 / 写真ごとの実設定
    ↓
アプリ全体のデフォルト設定
```

全体デフォルトは許可そのものではなく、新規写真作成時の初期値にすぎない。

## 12. B2C共有ページへの自動反映

`customerVisible = true` の写真のみ共有候補とする。

### 受付〜承認

```txt
reception + front
reception + back
```

### 作業中

OH時:

```txt
work + movement_open
```

その他修理:

```txt
work + repair_detail
```

共有ページ側でOH判定を複雑に持つより、撮影したカテゴリに従って表示する方向を優先する。

### 作業完了

```txt
completion + front
```

必要に応じ `completion + back` 等も追加表示可能。

---

## 13. PublicCaseへの利用

写真分類により、PublicCase編集時の候補を整理できる。

候補例:

```txt
メイン候補 = completion + front
Before候補 = reception + front / back
作業工程候補 = work + movement_open / repair_detail
```

`publicCaseVisible = true` の写真だけ候補に出す。

自動でPublicCase公開写真を確定せず、最終選択は人が行う。

---

## 14. SNSへの利用

`snsVisible = true` の写真だけSNS投稿候補として扱う。

自動投稿は別Taskとし、写真フラグだけで即時投稿しない。
