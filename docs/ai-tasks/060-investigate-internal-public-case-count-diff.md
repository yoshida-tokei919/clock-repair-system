## 差分概要

内装Excelの `掲載判定_全件` で `掲載可否` が `掲載候補` または `掲載候補（要最終確認）` の行について、Excel側の `件数` 合計と、FMP CSVの `内装修理内容1〜3` を原文完全一致で集計した件数を突き合わせた。

| 集計元 | 件数 |
| --- | ---: |
| Excel掲載候補明細件数 | 2624 |
| CSV原文完全一致の掲載候補明細件数 | 2621 |
| 差分 | 3 |

差分は以下2種類の原文で発生している。

| Excelルール原文 | Excel件数 | CSV完全一致件数 | 差分 |
| --- | ---: | ---: | ---: |
| 電池交換 | 433 | 431 | 2 |

## 原因分析

差分原因は、CSV側の内装修理内容末尾に垂直タブ相当の制御文字 `0x0B` が含まれていること。

該当CSV値は以下。

```txt
電池交換\x0B
電池交換\x0B
半OH\x0B
```

Excel側の掲載ルールは制御文字なしの原文で集計されている。

```txt
電池交換
半OH
```

そのため、CSVを完全一致だけで突合すると3件が掲載候補ルールに一致しない。一方、制御文字を除去して比較すると、3件とも既存の掲載候補ルールへ一致する。

今回確認した範囲では、差分原因は前後スペース、全角/半角、Excel側の基準差ではなく、CSV側の制御文字混入。

## 修正方針案

※今回はファイル本体は修正しない。

次に集計・取り込み処理を作る場合は、CSV/Excel本体を書き換えず、読み込み時に比較用キーだけ正規化する。

候補:

```ts
function normalizeRepairWorkNameForMatch(value: string) {
  return value.replace(/[\x00-\x1F]+/g, "").trim();
}
```

注意:

- 正規化は突合用キーに限定し、元原文は監査・確認用に保持する。
- 未レビュー221種類を正規化によって掲載候補へ戻さない。
- `交換` は引き続き `交換技術料` とし、部品名付き作業名へ分解しない。
- CSV/Excel本体は変更しない。

- 差分になった制御文字付きCSV値と修理IDを出力する。

DB接続、DB更新、CSV/Excel上書きは行わない。

