# B2B共有画面仕様

## 目的

B2B共有画面は、取引先がログインなしで修理案件と見積内容を確認するための画面。

この画面では、取引先向けに必要な情報を出すが、管理画面と同じ内部表現をそのまま出さない。

## アコーディオンUI

B2B共有画面では、複数案件をアコーディオンで表示する。

目的:

- 複数案件の一覧性を保つ
- スマホで1案件ずつ確認しやすくする
- 金額、時計情報、コメント、PDFへの導線を案件単位で整理する

## 案件カード表示ルール

カード上部:

- 1行目: ステータスチップ
- 2行目: エンドユーザー名 / 管理番号 / お問合番号
- 3行目: ブランド / モデル名
- 4行目: Ref / Serial

出さない表現:

- `お客様 様`
- `氏名未登録`
- `管 -`
- `貴社管理番号:`
- `案件番号:`

## 名前の扱い

重要:

```txt
B2B共有カードの名前 = Repair.endUserName
B2B共有先名 = Customer.name / companyName
B2C顧客名 = Customer.name
```

「顧客名」という曖昧な表現は避ける。

B2B共有カードでは「エンドユーザー名」と書く。

## 管理番号 / お問合番号ルール

管理番号:

- アプリ側の案件管理番号
- 主に`Repair.inquiryNumber`

お問合番号:

- 取引先側の参照番号
- 主に`Repair.partnerRef`

表示方針:

- 値がない場合に`管 -`のようなノイズを出さない
- B2B共有先が案件を識別しやすい表現にする

## ステータスサマリー判定

B2B共有ページでは、複数案件の進行状況をサマリー表示する。

方針:

- 承認済み案件数
- 未承認/確認待ち案件数
- 案件ごとの状態

注意:

- ステータス文言は業務フローに合わせる
- 表示目的は取引先の判断支援であり、内部管理用の全statusをそのまま出すとは限らない

## コメントsenderType

`RepairCustomerMessage.senderType` はコメントの送信者種別を表す。

想定:

- `partner`: 取引先
- `admin`: 管理者/工房側

注意:

- ローカルDBで古いmigration状態の場合、`senderType` columnがない可能性がある
- B2B共有ページの表示にはschema/migration状態の整合が必要

## 貴社専用メモ

B2B共有画面には、取引先が自分向けに残すメモ機能がある。

方針:

- 管理者向け内部メモとは分ける
- 取引先が混乱しないラベルにする
- 案件単位で保存・表示する

## PDFボタンの扱い

現在:

- public PDF routeへリンクする
- route側でPDFを生成している箇所が残っている

最終方針:

- PDFボタンは既存URLを維持
- `/customer/repairs/[token]/estimate.pdf`
- route内ではPDFを生成しない
- `EstimateDocument.currentPdfFileId → EstimatePdfFile.storageKey`を使って保存済みPDFを返す

PDF未生成時:

- 自動生成しない
- 404またはPDF未生成エラー
- 管理画面で先に生成・確認する運用にする

絶対方針:

```txt
ログイン不要 = 別PDFを作る、ではない
同じPDFを、token認証で見せる
```
