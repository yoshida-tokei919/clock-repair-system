# LINE Manager observed outbound sync: local implementation

This local worker reads authenticated Manager `messageSent` TEXT history for server-listed verified bot/chat mappings. The import API records independent `LineManagerObservedOutbound` rows. It never creates or changes `InquiryMessage` or confirms `LineManagerSendOutbox`. An event `sendId` does not prove it came from this app or a smartphone.

`scripts/line_manager_observed_sync.py` is dry-run count-only by default. `--apply` is explicit and requires both `N8N_INTERNAL_TOKEN` and a separately provisioned `LINE_MANAGER_SYNC_SIGNING_KEY`. The signing key must be 32 high-entropy random bytes encoded as exactly 64 lowercase hex characters; both sides decode the hex to key bytes before HMAC. Other formats fail closed. The fixed origin is production, with `--local` allowed only for local tests. There is no schedule or n8n wiring. Never put either secret in command arguments or logs. A failed apply reports counts as unknown with `possiblePartial: true` because earlier batches may have committed.

The import endpoint requires the internal Bearer token plus `X-Line-Manager-Sync-Timestamp` (Unix seconds) and `X-Line-Manager-Sync-Signature` (lowercase hex SHA-256 HMAC). The signed bytes are UTF-8 timestamp, a dot, then the exact raw JSON request bytes. The signing key must be independently provisioned on worker and server. This is trusted worker attestation of a read, **not cryptographic LINE proof**. The two-minute timestamp window is not a nonce store; replayed identical events are compared against immutable stored evidence and do not update existing rows.

The worker reads only the recent first page (at most 100 history items per chat). Manager returns `backward` even on short pages, so output always reports `historyComplete: false`, and `hasEarlierHistory` reflects the cursor. Deferred events may leave this window before a retry. This coverage gap is an **activation blocker for reliable historical or full sync**; do not schedule the worker. Mapping listing uses pages of at most 20, with a hard ceiling of 1000; exceeding it fails closed with `mappingsIncomplete: true`. A future pagination implementation needs independently verified cursor progress and termination first.

The existing Outbox confirmation transaction now takes the same advisory lock as import. If it confirms an exact observed bot/message ID, it removes the matching observed row in the same transaction. Conflicting observed evidence aborts confirmation. This sender confirmation change requires a separate, narrowed independent re-review before activation.

Activation prerequisites: the foundation migration containing `LineManagerObservedOutbound` must be applied in production under separate approval; provision the signing key under separate approval without displaying it; review test results and worker output; explicitly approve any live Manager read, real import, scheduling, deployment, or production migration. None is performed by this local task.
